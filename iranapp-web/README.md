# ایران آپ - نسخه تحت وب

نسخه وب (PWA) اپلیکیشن اندروید ایران آپ. همان امکانات اپ را دارد، با همان API کار می‌کند و برای کاربران iOS و هر دستگاهی است که نمی‌تواند نسخه اندروید را نصب کند.

- آدرس پیش‌فرض: `https://iranapp.biz/web/`
- بک‌اند: همان `iranapp-api` (هیچ تغییری در سرور لازم نیست)

## ابزارها

| بخش | کتابخانه |
|---|---|
| پایه | React 19، TypeScript، Vite |
| مسیرها | React Router |
| داده‌ها | TanStack Query (کش، لیست‌های بی‌پایان)، Axios |
| وضعیت کاربر | Zustand (ذخیره در localStorage) |
| ظاهر | Tailwind CSS v4 |
| آیکون‌ها | آیکون‌های خود اپ (تبدیل‌شده به SVG) و `@mdi/js` |
| اسلایدر عکس | Embla Carousel |
| نقشه | Leaflet + OpenStreetMap |
| نصب روی گوشی | vite-plugin-pwa |
| اعلان (اختیاری) | Firebase Cloud Messaging |

## اجرا روی سیستم خودتان

```bash
npm install
npm run dev
```

برنامه روی `http://localhost:5173/web/` باز می‌شود. در حالت dev درخواست‌های `/api` و عکس‌ها به سرور اصلی (`http://iranapp.biz`) فرستاده می‌شوند، پس **هر ثبت‌نام، آگهی یا لایکی که در این حالت انجام دهید واقعی است**.

برای کار با API محلی، یک فایل `.env` بسازید (نمونه: `.env.example`):

```
VITE_DEV_BACKEND=http://127.0.0.1:8000
```

و در پوشه `iranapp-api` سرور را بالا بیاورید: `php artisan serve`.

## ساخت و انتشار روی هاست

```bash
npm run build
```

خروجی در پوشه `dist` ساخته می‌شود. روی هاست Node لازم نیست.

1. در File Manager هاست، پوشه `public_html/web` را بسازید.
2. **همه محتویات** پوشه `dist` را داخل آن آپلود کنید. فایل `.htaccess` هم جزو خروجی است؛ مطمئن شوید آپلود شده (در بعضی File Managerها فایل‌های نقطه‌دار پنهان‌اند).
3. آدرس `iranapp.biz/web` را باز کنید.

برای به‌روزرسانی، دوباره build بگیرید و فایل‌ها را جایگزین کنید. کاربران با باز کردن دوباره برنامه نسخه جدید را می‌گیرند.

پنل ادمین (`/admin`) و API (`/api`) دست نمی‌خورند: فایل `.htaccess` داخل `web` فقط آدرس‌های زیر `/web` را به برنامه می‌دهد.

### HTTPS لازم است

بدون HTTPS این قابلیت‌ها در مرورگر کار نمی‌کنند:

- موقعیت مکانی («اطراف من» و شروع نقشه از محل کاربر)
- نصب روی صفحه اصلی گوشی و کار آفلاین (Service Worker)
- اعلان‌ها

بقیه برنامه روی HTTP هم کار می‌کند. عکس‌ها مشکلی با HTTPS ندارند: لینک‌های `http://iranapp.biz/...` که API برمی‌گرداند به مسیر همان دامنه تبدیل می‌شوند.

### تغییر مسیر

برای مسیری غیر از `/web` (مثلاً `/app`):

1. در `.env` بگذارید `VITE_BASE_PATH=/app/`
2. در `public/.htaccess` دو جای `/web/` را عوض کنید
3. دوباره build بگیرید

## تنظیمات (`.env`)

همه اختیاری‌اند. فهرست کامل در `.env.example`.

| متغیر | کار |
|---|---|
| `VITE_BASE_PATH` | مسیر برنامه روی دامنه (پیش‌فرض `/web/`) |
| `VITE_API_BASE` | آدرس API (پیش‌فرض `/api` روی همان دامنه) |
| `VITE_REQUIRE_LOGIN` | اپ اندروید بدون ورود اجازه استفاده نمی‌دهد و نسخه وب هم همین‌طور است. با `false` مهمان‌ها هم می‌توانند آگهی‌ها را ببینند |
| `VITE_MAP_TILE_URL` | سرور کاشی نقشه، اگر خواستید از سرویس دیگری (مثلاً نشان) استفاده کنید |
| `VITE_FIREBASE_*` | اعلان‌های وب (پایین را ببینید) |

## اعلان‌های وب (اختیاری)

تا وقتی مقادیر Firebase تنظیم نشده‌اند، گزینه «دریافت اطلاعیه ها» فقط پیام می‌دهد که اعلان فعال نیست و بقیه برنامه عادی کار می‌کند.

برای فعال کردن:

1. در کنسول Firebase، پروژه `iranapp-fc361` > Project settings > Add app > Web.
2. مقادیر `apiKey`، `messagingSenderId` و `appId` را در `.env` بگذارید.
3. از تب Cloud Messaging > Web Push certificates یک کلید بسازید و در `VITE_FIREBASE_VAPID_KEY` بگذارید.
4. دوباره build بگیرید.

در آیفون اعلان فقط از iOS 16.4 به بالا و فقط بعد از «Add to Home Screen» کار می‌کند. دسترسی به سرویس Firebase از داخل ایران هم همیشه پایدار نیست.

## ساختار پروژه

```
src/
  config.ts            تنظیمات build و ثابت‌ها
  App.tsx              مسیرها و شرط ورود
  lib/
    http.ts            کلاینت HTTP (توکن، خروج خودکار با توکن منقضی)
    api.ts             یک تابع برای هر endpoint
    types.ts           شکل پاسخ‌های API
    jalali.ts          تاریخ شمسی
    labels.ts          فهرست‌های ثابت و برچسب‌های فارسی
    categoryIcons.ts   انتخاب آیکون از روی نام دسته
  store/
    session.ts         کاربر، توکن، شهر انتخاب‌شده
    ui.ts              پیام‌ها و دیالوگ‌های سراسری
  components/          اجزای مشترک (کارت آگهی، فرم، دیالوگ، نقشه، ...)
  pages/               صفحه‌ها؛ هر کدام معادل یک Activity یا Fragment اپ
  assets/              آیکون‌ها، تصاویر و فونت‌های اپ اندروید
  content/             متن قوانین و جدول آیکون دسته‌ها (تولیدشده)
scripts/
  import-android-assets.py   آیکون‌ها، تصاویر، فونت و متن‌ها را از سورس اندروید می‌آورد
```

اگر آیکون یا متن قوانین در اپ اندروید عوض شد: `npm run import-assets`

## تفاوت‌های نسخه وب با اپ

- **آگهی خودرو، املاک و استخدام لینک مستقیم ندارند.** API برای این سه نوع «دریافت با شناسه» ندارد (اپ هم کل آگهی را از لیست به صفحه جزئیات می‌دهد). صفحه جزئیات بعد از refresh کار می‌کند، ولی اگر لینکش را برای کس دیگری بفرستید پیام «در دسترس نیست» می‌بیند. آگهی‌های کسب و کار این محدودیت را ندارند.
- **نقشه** به‌جای Google Maps از OpenStreetMap است.
- **برش عکس** قبل از آپلود وجود ندارد؛ عکس‌ها فقط کوچک و فشرده می‌شوند.
- **خواندن خودکار کد پیامک** به روش اندروید ممکن نیست؛ به‌جایش پیشنهاد کد صفحه‌کلید گوشی (iOS و اندروید) پشتیبانی می‌شود و با کامل شدن کد، خودکار ارسال می‌شود.
- **دکمه ایتا** با لینک `et://` کار می‌کند، یعنی فقط وقتی برنامه ایتا روی دستگاه نصب باشد.
- صفحه شروع به‌جای ۴ ثانیه حدود ۲ ثانیه نمایش داده می‌شود.
- در صفحه‌های ورود، ثبت‌نام و تأیید شماره لینک‌های کوچک جابه‌جایی («ثبت نام»، «ورود»، «خروج») اضافه شده، چون در مرورگر دکمه برگشت اپ وجود ندارد.
- در منو گزینه «نصب برنامه روی گوشی» اضافه شده است.

## فونت

فونت برنامه همان فونت اپ اندروید است (`IRANYekan` نسخه FaNum که اعداد را فارسی نشان می‌دهد). این فونت تجاری است و مجوز استفاده در وب از مجوز موبایل جداست؛ قبل از انتشار عمومی مجوز وب آن را بررسی کنید. برای جایگزینی با یک فونت آزاد (مثلاً وزیرمتن)، فایل فونت را در `src/assets/fonts` بگذارید و `@font-face` اول `src/index.css` را عوض کنید.
